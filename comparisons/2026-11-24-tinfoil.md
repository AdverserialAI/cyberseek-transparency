# Side-by-side review: Tinfoil and Adverserial (24 November 2026)

This file records how the comparison published in our blog post was produced, so that anyone can
repeat it. Read these three points first.

* **It was run by Adverserial, not by an independent party.** Treat it as a reviewer's procedure you
  can re-run, not as a third-party audit.
* **Only public material was used and no account was created on either service.** No prompt was
  sent to either service, so inference itself was not tested.
* **The two runs were not symmetric.** Tinfoil was checked in steady state. Adverserial was checked
  on the day of a platform migration: its endpoint was restarting for the whole window
  (16:13 to 16:51 UTC), so no live verification of Adverserial passed that day. Rows that depend on
  the live endpoint are marked *pending* in the blog and will be re-run.

## What was observed

**Tinfoil.** Their open-source CLI, built from source at commit `ceb5443`, verified the public
router enclave (`inference.tinfoil.sh`, AMD SEV-SNP) and one GPU model enclave. The result was
cross-checked by hand: the live TLS key equals the key in the hardware report, the HPKE key is bound
in the same report, and the expected measurement comes from a Sigstore bundle on the GitHub release
(Rekor log index 3978410112) signed by the tagged release workflow. Not confirmed: the image
rebuild was not attempted, no build provenance was found for the router container image with the
two lookups below, and no GPU evidence was observed.

**Adverserial.** The live endpoint failed the TLS handshake on all seven polls, and the verifier in
this repository exited 3 ("could not fetch"). Everything that does not need the live endpoint
reproduced: the compose hash, the GPU policy hash, the OS image hash from the public download, the
proxy image's build provenance, and the Sigstore attestations on the deployment files. The client
policy was still unsigned at the time of the run; signing went live later the same day (see
`AdverserialAI/confidential-policy`, `SIGNING.md`).

## Commands: Tinfoil

Use empty directories. `HOME` is pointed at a scratch directory so the CLI keeps no state in yours.

```sh
git clone --depth 1 https://github.com/tinfoilsh/tinfoil-cli && cd tinfoil-cli
GOWORK=off GOTOOLCHAIN=auto go build -o ../tinfoil . && cd ..
export HOME=$PWD/tfhome TINFOIL_NO_UPDATE_CHECK=1
./tinfoil attestation verify -e inference.tinfoil.sh -r tinfoilsh/confidential-model-router -j -l router.json

# the live TLS key, to compare with the first 32 bytes of report_data
echo | openssl s_client -connect inference.tinfoil.sh:443 -servername inference.tinfoil.sh 2>/dev/null \
  | openssl x509 -noout -pubkey | openssl pkey -pubin -outform der | shasum -a 256
curl -s https://inference.tinfoil.sh/.well-known/tinfoil-attestation -o att.json
python3 -I -c 'import json,base64,gzip;r=gzip.decompress(base64.b64decode(json.load(open("att.json"))["body"]));print(r[0x50:0x90].hex());print(r[0x90:0xC0].hex())'

# the signed release the measurement is compared with
gh release download v0.0.179 -R tinfoilsh/confidential-model-router
shasum -a 256 tinfoil-deployment.json
gh attestation verify tinfoil-deployment.json -R tinfoilsh/confidential-model-router \
  --predicate-type https://tinfoil.sh/predicate/snp-tdx-multiplatform/v1 --format json
curl -s "https://rekor.sigstore.dev/api/v1/log/entries?logIndex=3978410112"
jq -r .config tinfoil-deployment.json | base64 -d | shasum -a 256

gh release download v0.14.19 -R tinfoilsh/cvmimage -p '*manifest*'
gh attestation verify tinfoil-inference-v0.14.19-manifest.json -R tinfoilsh/cvmimage
./tinfoil attestation verify -e deepseek-v4-1-flash-inf22-0.tinfoil.containers.tinfoil.dev \
  -r tinfoilsh/confidential-deepseek-v4-1-flash
curl -s https://inference.tinfoil.sh/.well-known/tinfoil-proxy

# the two lookups that found no provenance for the router container image (404 / nothing)
gh attestation verify oci://ghcr.io/tinfoilsh/confidential-model-router@sha256:6531d8e2981166da6248b7b52e8dbe8412eb591f7564bb5f6afba541cf9042bb \
  -R tinfoilsh/confidential-model-router
cosign tree ghcr.io/tinfoilsh/confidential-model-router@sha256:6531d8e2981166da6248b7b52e8dbe8412eb591f7564bb5f6afba541cf9042bb
```

## Commands: Adverserial

```sh
N=$(python3 -I -c 'import os,base64;print(base64.urlsafe_b64encode(os.urandom(32)).rstrip(b"=").decode())')
for p in "/attestation?nonce=$N" /statusz /.well-known/adverserial-key-attestation \
         /.well-known/adverserial-meter-jwks.json /.well-known/hpke-keys; do
  curl -sS -m 25 -o /dev/null -w "%{http_code}\n" "https://api.adverserial.ai$p"; done

git clone https://github.com/AdverserialAI/cyberseek-transparency && cd cyberseek-transparency
python3 -m venv ../venv && ../venv/bin/python -m pip install --require-hashes -r verify/requirements.txt
../venv/bin/python verify/verify.py https://api.adverserial.ai --deployment "deployments/$(head -n 1 deployments/CURRENT)"; echo $?

D="deployments/$(head -n 1 deployments/CURRENT)"
shasum -a 256 $D/app-compose.json                                   # the published compose hash
jq -j .docker_compose_file $D/app-compose.json | shasum -a 256; shasum -a 256 $D/docker-compose.yml
printf '%s' '{"attest_gpu":false}' | shasum -a 256; jq -c .requirements $D/app-compose.json
../venv/bin/python tools/validate_deployments.py; ../venv/bin/python tools/check_no_secrets.py deployments/
for f in app-compose.json docker-compose.yml policy.json; do
  gh attestation verify $D/$f --repo AdverserialAI/cyberseek-transparency; done
gh attestation verify oci://ghcr.io/adverserialai/attest-proxy@sha256:5a41bcfb6d7f4f3d3df53ad5ac39a45d1d32a6db206e35c0380b81d56404824b \
  -R AdverserialAI/attest-proxy --format json
../venv/bin/python history/check_chain.py; wc -c history/attestations.jsonl

# the guest OS image: the hash is recomputable; the archive carries no build provenance
curl -sSLO https://github.com/Dstack-TEE/dstack/releases/download/mkosi-os-v0.6.5/dstack-0.6.5.tar.gz
tar -xzOf dstack-0.6.5.tar.gz dstack-0.6.5/sha256sum.txt | shasum -a 256
gh attestation verify dstack-0.6.5.tar.gz -R Dstack-TEE/dstack

# the client policy and its signature
curl -sSO https://verify.adverserial.ai/policies/production.json
curl -sSO https://verify.adverserial.ai/policies/production.json.sigstore.json
cosign verify-blob --bundle production.json.sigstore.json \
  --certificate-identity https://github.com/AdverserialAI/confidential-policy/.github/workflows/sign-policy.yml@refs/heads/main \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  --certificate-github-workflow-trigger push production.json
git ls-remote https://github.com/AdverserialAI/confidential-policy signed
```

Source read for the rows that could not be observed running, at `AdverserialAI/attest-proxy` tag
`v0.1.0-rc.33`: `internal/enclavekeys/enclavekeys.go` and `internal/config/config.go` (key
generation and the refusal of outside keys), `internal/gate/cache_salt.go` (cache separation),
`internal/server/server.go` (route allowlist), `internal/proxy/proxy.go` (what is logged).

## What this comparison does not show

* It does not show that either service's builds are reproducible: no rebuild was done.
* It does not compare GPU attestation on evidence: no GPU evidence was observed from either.
* It does not confirm or doubt either service's logging and retention statements: they are documented only.
* It does not show that Tinfoil lacks container provenance in general: only two lookups returned nothing.
* It does not show that Adverserial's live service passes verification: on that day it did not.
